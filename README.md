# wechat-db-key

> 微信 4.x（Windows）本地数据库密钥的**提取**与**校验**工具。
> 只读、本地运行、不上传任何数据。

微信本地聊天库是 SQLCipher 加密的，读内容需要一把 32 字节的密钥。
这个仓库存两件事：

- `verify_key.py` — 手上有一把 key，判断它对不对（**毫秒级**，不用解密全库）
- `extract_key.py` — 从运行中的微信进程内存里把 key 找出来

---

## 为什么值得用

网上提取微信密钥的工具不少，但大多有两个毛病：**要么只提取不校验**（拿到假 key 也不自知），
**要么假定一切顺利**（失败时只说"没找到"，不告诉你为什么）。

这个仓库的重点是**确定性**：

1. **每把 key 都过 HMAC 校验**，不是"看起来像"就算数
2. **校验器可以单独用**——别人给你一把 key、或你一年前存的，都能当场验真伪
3. 附带一份**实测过的踩坑清单**，把"为什么找不到"拆成可逐步排查的原因

## 快速开始

```bash
pip install psutil

# 1. 校验一把已有的 key
python scripts/verify_key.py <64位hex密钥> "C:\Users\<你>\Documents\xwechat_files\<wxid>_xxxx\db_storage"

# 2. 从运行中的微信提取
python scripts/extract_key.py --db "<db_storage目录>" --dump

# 3. 扫不到？重启微信后立刻扫
python scripts/extract_key.py --db "<db_storage目录>" --restart
```

提取需要**管理员权限**，且微信必须**已登录并正在运行**。

## 验证状态（说在前面）

| 部分 | 状态 |
|---|---|
| `verify_key.py` 的 HMAC 校验算法 | ✅ 实测通过：真 key 命中，全 0 假 key 不匹配 |
| 异或还原链路（`raw XOR xor_key → final`） | ✅ 实测通过：能还原出历史上真实生效的密钥 |
| 候选值的熵/字符分布筛选 | ✅ 已实现并跑过（结论见下方"为什么不能盲扫"） |
| 内存**特征定位**（`SIG_TAIL`） | ⚠️ 逻辑完整，但在测试机上未跑到端到端成功——因为需要微信冷启动窗口期，测试时微信已运行一整天，特征命中为 0 |

最后一项是这套方案里唯一依赖**版本特征**的环节。诚实说：它能否在工作机上一次跑通，
取决于你的微信版本是否与特征匹配。**但即使定位失败，校验器依然完全可用**——
你可以从任何渠道拿到候选 key，用它快速判真伪。

## 原理

### 校验（为什么毫秒级）

SQLCipher 4 在加密库的**第一页**里存了一段 HMAC-SHA512 校验码。校验流程：

```
salt    = page[0:16]
mac_salt = salt XOR 0x3a
enc_key = PBKDF2-SHA512(passphrase, salt, 256000 轮, 32 字节)
mac_key = PBKDF2-SHA512(enc_key, mac_salt, 2 轮, 32 字节)
HMAC-SHA512(mac_key, page[16 : 4096-80+16] + 页号)  ==  page 里存的校验码 ？
```

只读 4096 字节，命中即判定 key 正确。不用解密整个库（那些动辄几百 MB）。

### 提取（三步）

```
① 定位   微信打开数据库时堆上有内部结构，带固定字节特征，结构里有指针
              ↓
② 读值   顺着指针读 32 字节 = raw
              ↓
③ 还原   raw XOR xor_key = 最终口令   （xor_key 藏在 Weixin.dll 里，版本相关）
```

## 实测发现（这些坑我替你踩过了）

### 1. 内存里没有明文最终密钥

试过"用数据库文件的 salt 当锚点，去内存里找附近的 key"——**失败**。
扫完 1000MB 内存，salt 出现 10 次，附近没有任何最终密钥。

因为最终口令是 `raw XOR xor_key` **算出来的**，用完不留在内存里。

### 2. 盲扫不可行

不做特征定位，只按「32 字节 + 高熵」筛，实测得到 **5,709,492 个候选**。
每个候选一次 PBKDF2（256000 轮）≈ 几十毫秒 → 算完要几十小时。

**结论：必须先精确定位，不能蛮干。**

### 3. 特征结构只存在于冷启动窗口期

微信跑一整天后再扫，特征命中 = **0**。那个内部结构早就释放或重建了。
要抓到，得在微信**刚启动、刚打开数据库**的那几十秒内扫。

这就是 `--restart` 参数的意义。

### 4. 不需要 YARA

社区工具常用 YARA 规则做特征匹配。但那条规则本质就是**固定字节序列**，
用 Python 的 `bytes.find()` 完全可以实现——所以本仓库**零额外依赖**（只要 `psutil`），
不用编译 `yara-python`。

## 失败排查（按顺序）

1. **微信登录了吗？** 未登录时内存里根本没有密钥
2. **有管理员权限吗？** 否则 `OpenProcess` 直接失败
3. **PID 对吗？** 微信有 5~6 个进程，要选内存占用最大的主进程
4. **微信跑太久了吗？** 加 `--restart` 重启后立刻扫
5. **XOR 常量给了吗？** 4.x 通常需要，不给就只能验证 `raw`
6. **数据目录对吗？** 多账号时最容易指向未登录的那个账号
7. 全对还不行 → 微信升级导致特征失效
